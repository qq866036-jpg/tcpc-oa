## 6. 安装 OCR 服务（先 RapidOCR 跑通）

```bash
# ① 目录 + venv
install -d -m 0755 /opt/tcpc-ocr
python3 -m venv /opt/tcpc-ocr/venv
/opt/tcpc-ocr/venv/bin/pip install -U pip
/opt/tcpc-ocr/venv/bin/pip install -r "$OA/scripts/ocr-service/requirements.txt"

# ② 部署服务文件
install -m 0755 "$OA/scripts/ocr-service/app.py" /opt/tcpc-ocr/app.py
install -m 0644 "$OA/scripts/ocr-service/tcpc-ocr.service.example" /etc/systemd/system/tcpc-ocr.service

# ③ 改两处再启动：User/Group 按实际（www），TCPC_OCR_ROOTS = 真实存储根
#    存储根取值（插件侧同源）：wp eval 'echo zw_receipt_storage_root();' --path=/www/wwwroot/tcpc.org.cn --allow-root
sed -n '/TCPC_OCR_ROOTS/p' /etc/systemd/system/tcpc-ocr.service
systemctl daemon-reload && systemctl enable --now tcpc-ocr
systemctl status tcpc-ocr --no-pager | head -5

# ④ 自检
curl -s http://127.0.0.1:8848/health | python3 -m json.tool
# 预期：{"ok": true, "engine": "rapidocr", "engine_version": "...", "models_ready": true, "error": ""}
```

**首次调用会加载/下载模型**（约 10–20MB 级），`/health` 首次可能 `models_ready:false` 但 `error` 为空 —— 再等几秒重试。

**失败处置**：
| 现象 | 处置 |
|---|---|
| `ModuleNotFoundError: rapidocr` | 第 ① 步没装成功（venv 路径错？pip 源慢？）；重跑 pip install |
| `models_ready:false` 且 `error` 非空 | 按 error 原文处理（多半是模型下载失败/磁盘满） |
| 端口占用 | `ss -lntp \| grep 8848` 查占用者，或改端口（插件设置页同步改） |

**回滚**：`systemctl disable --now tcpc-ocr`（插件侧不打开关即零行为）。

## 7. 插件后台开启 OCR

后台路径：**办公协同 → 收文管理 → 收文台账 → 右上「OCR 识别设置」**（或直接
`/wp-admin/admin.php?page=zw-receipt-ledger&view=ocr`）。

1. 勾「启用 OCR」；
2. 端点填 `http://127.0.0.1:8848/ocr`（**不要**填公网域名，会被白名单拒绝）；
3. 令牌：若服务端设了 `TCPC_OCR_TOKEN`，这里填同一个值；没设就留空；
4. 点「测试连接」→ 预期绿色提示「自检通过：引擎：rapidocr；版本：…；模型：已就绪」；
5. 「保存设置」。

**回滚**：取消勾选并保存（`zw_ocr_enabled=0`，零行为）。

## 9. 质量抽检（决定是否切 PaddleOCR）

拿 **3 份真实来文**（建议：① 红头文件正文页 ② 带表格的附件页 ③ 扫描歪斜或竖排件），各跑一次：

```bash
# 直接问服务（把 PATH 换成实际存储根内的文件）
curl -s -X POST http://127.0.0.1:8848/ocr \
  -H 'Content-Type: application/json' -H "X-TCPC-OCR-Token: $TOKEN" \
  -d '{"path":"/www/zw-office-files/receipts/民政部/2026/示例.pdf"}' | python3 -c \
  'import json,sys; d=json.load(sys.stdin); print("ms=",d.get("ms"),"conf=",d.get("confidence"),"lines=",d.get("lines")); print(d.get("text","")[:300])'
```

判定口径（工程约定，非国标）：

| 观察 | 结论 |
|---|---|
| 正文行准确、标题/落款基本可读，`conf ≥ 85` | **RapidOCR 够用**，留在生产 |
| 正文错字多、表格串行、`conf < 75` | **切 PaddleOCR**：`pip install -r "$OA/scripts/ocr-service/requirements-paddle.txt"`，systemd 加 `Environment=TCPC_OCR_ENGINE=paddleocr`，重启后 `/health` 里 `engine` 应变 `paddleocr` |
| 印章压字导致整行缺失 | 记录为已知限制（两家通用 det 都会当噪声）；后续可上 PP-StructureV3 版面分块 |

抽检结论写进 `docs/` 下当次发布记录（含 3 个样本的耗时/置信度/主观评级）。

## 11. 禁止事项（窗口内）

- ❌ 不要 `DROP`/`TRUNCATE` 任何收文相关表；不要改 `zw_policy_issue` 的状态语义。
- ❌ 不要把 OCR 服务绑到 `0.0.0.0`，不要用公网地址填端点（公文不出服务器，双端都会拒）。
- ❌ 不要在生产 `wp eval-file` 跑任何**非本清单**的脚本。
- ❌ 不要为了"让 OCR 快"把超时调到 5 秒以下（大 PDF 会批量失败，反而更多重试）。
- ❌ 不要跳过 `/bhzc` 哈希校验（铁律 19）。
