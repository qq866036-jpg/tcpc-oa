# OA-2468 · 收文自动办理：批示库 + 20 秒自动签阅

- 任务：**OA-2468**（主题载体单 `TASK-2554`）｜ 日期：2026-11-03 ｜ 状态：已并入 dev（未部署）
- 用户指令原文：
  > 「领导批示 和 签阅 为我根据 政治站位编一个 批示库，签阅 在收文20秒后设置一个签名 时间戳即可」

## 1. 口径落地

| 用户要求 | 实现 |
|---|---|
| 领导批示不用等真人 | **批示库**：7 类政治站位模板（21 条），后台可增删改；系统按「关键词 → 类别 → 确定性轮换」选一条，写入 `zw_receipt_handle_log`（action=`instruction`） |
| 签阅不用点按钮 | 登记成功后 **20 秒** 由 WP-Cron 写一条 `sign` 留痕，`created_at` 即**签名时间戳** |

## 2. 批示库

| 类别 key | 名称 | 命中关键词（示例） |
|---|---|---|
| `inspect` | 督查整改类 | 整改、督查、检查、通报、问题、清单 |
| `request` | 请示报告类 | 请示、报告、报请、申请、审批 |
| `hr` | 人事管理类 | 任免、干部、人事、招聘、职称、编制 |
| `finance` | 财务管理类 | 经费、预算、财务、资金、报销、审计 |
| `implement` | 贯彻落实类 | 贯彻、落实、学习、精神、意见、决定 |
| `deploy` | 部署落实类 | 通知、部署、安排、开展、实施、组织 |
| `routine` | 常规阅办类 | （兜底） |

- **匹配顺序固定**：督查整改 → 请示报告 → 人事 → 财务 → 贯彻落实 → 部署落实 → 常规阅办（先紧后松，避免「关于开展整改的通知」被部署类抢走）。
- **匹配文本**：标题 + 来文字号 + 来文单位 + OCR 文本前 2000 字（OCR 可用时才参与，不额外依赖）。
- **选词**：`crc32(receipt_id|category) % 条数` ⇒ 同一收文永远同一条（可复现、可审计），不同收文自然分散。
- 默认 21 条均为**通用政治站位口径**（无具体人名/事件），可在「收文自动化」页逐条改。

## 3. 自动签阅

- 触发：登记成功 → `zw_receipt_auto_after_register()` → `wp_schedule_single_event(time()+20, 'zw_receipt_auto_sign_event', [id])`。
- 写入：`action=sign`、内容「系统自动签阅：收文后 20 秒写入签名时间戳（YYYY-MM-DD HH:MM:SS）」，行时间即时间戳。
- 幂等：同收文已存在 `system:auto-sign` 的 sign 行即跳过（重复登记/重排不会写第二条）。
- 无 cron 通道（CLI/测试）当场写，保证行为可验证。

## 4. 诚实与可审计（硬边界）

- **不假冒真人账号**：自动条目 `author_login = system:auto-instruction` / `system:auto-sign`，
  `author_name` = 「系统自动（批示库）」/「系统自动签阅」；时间线渲染灰标「系统自动」。
- **不伪造事实**：批示是「系统按库生成」，不是「某领导批示」；签阅是「系统时间戳」，不是「某甲已阅」。
  两者在时间线、导出、审计里都与人做的区分得开。
- **可一键关**：两个开关默认**开**（用户要求），关掉即零行为（不写任何行）；设置页写明这一点。

## 5. 落点与兼容

- 复用 `zw_receipt_handle_log`，**不新增表/列、无需迁移**；新增内部动作 `sign` 只允许内部调用
  （`zw_receipt_handle_add($raw, $extra_actions, $system_login)`，人工表单仍只给 拟办/批示/催办 三项）。
- 详情页「拟办与批示」卡片顶部显示 **签名时间戳**；台账操作栏新增「自动化设置」入口（`view=auto`，不新增子菜单）。
- 不改变办理状态机（4 态 + 派生逾期）；不触碰 `zw_policy_issue`。

## 6. 未做（范围内明确排除）

- `auto_dispatch`（自动派单）/ `auto_circulate`（自动传阅）/ `auto_urge`（自动催办）/ `auto_archive`（自动归档）：
  设计已在 OA-2468 提案里给出，等你确认再建单；本单只做你点名的「批示库 + 20 秒签阅」。
- LLM 生成批示：不做。规则库已满足当前要求，接模型需另立合规评估（公文含内部信息、审计、成本）。

## 7. 上线方式（下次窗口）

1. 版本 0.1.8 → **0.1.9** 三处同改 + `plugin-switch-oa.sh`（**无数据库迁移**）；
2. 后台「收文管理 → 自动化设置」确认两个开关为开、按需改批示库；
3. 冒烟：登记一份测试收文 → 详情页应出现「系统自动（批示库）」批示 + 20 秒后「自动签阅」及签名时间戳；
4. 回滚：关开关或 `--rollback <ts>`；本单无表结构变更，回滚无残留。
